# Repository guidance

When creating or substantially revising this repository's human-facing documentation, read `skills/docs-writing/SKILL.md` and its relevant reference. Apply it to the reader's task. Mechanical corrections do not require loading a skill.

Keep the README focused on what the skills do, how to start, and how to use them. Put alternate installation routes and maintainer procedures in linked documents. Verify commands and publication status before presenting them as available.

Use the repository's `pr-writing` skill for PR titles and descriptions. Use `text-editing` when an editorial review is requested, not as a mandatory finishing step.

Keep published prose focused on its reader. Remove migration history, conversation references, and editing or verification narration unless that history is necessary to use or maintain the artifact. Add external links to `docs/references.md`; skill-specific links must remain usable when a skill is installed alone.
